# Performance & SEO

The public site is a **student recruitment tool**. Most prospective students
arrive on a mid-range Android phone over 3G. If the homepage takes six seconds,
the application never gets started. These budgets are product requirements, not
engineering vanity.

---

## 2. How the budget is protected

### Server components by default

The biggest lever. A server component ships **zero** JavaScript. Only
`providers`, `header`, `language-switcher`, `contact-form` and `error` are
client components.

Push `"use client"` to the leaves. Marking a layout as client makes its whole
subtree client — that alone can blow the 200KB budget.

### Fonts

`next/font/google` self-hosts Poppins, Inter and JetBrains Mono at build time:
no render-blocking request to `fonts.googleapis.com`, no FOIT. `display: "swap"`
plus reserved metrics keeps CLS ~0.

> Requires network access **at build time**. In an offline/sandboxed CI, the
> build fails with "Failed to fetch `Inter` from Google Fonts" — allowlist
> `fonts.googleapis.com` + `fonts.gstatic.com` for the build step.

### Images

Always `next/image` — never a bare `<img>`:

```tsx
<Image src={url} alt="" width={800} height={450} quality={85}
       sizes="(max-width: 768px) 100vw, 33vw" placeholder="blur" />
```

Configured in `next.config.ts`: AVIF/WebP, device sizes
`320/640/768/1024/1200/1920`.

- Give **every** image explicit `width`/`height` (or `fill` + a sized parent).
  Unsized images are the number one cause of CLS.
- `priority` on the LCP image only. On everything = on nothing.
- New media host? Add it to `images.remotePatterns` or Next refuses to optimise it.

### ISR

| Route           | Revalidate |
| --------------- | ---------- |
| Homepage        | 1h         |
| News, events    | 1h         |
| Programs, about | 24h        |

Pages are served static from cache and refreshed in the background — visitors
never wait on the API.

> `export const revalidate` must be a **literal number**. Next analyses segment
> config statically; an imported constant silently doesn't apply (and now errors
> the build). See ARCHITECTURE.md §4.

### React Query stale times

`lib/query-keys.ts`: programs 30m · news/events 5m · profile 5m · results 15m ·
notifications 1m.

### Proxy matcher

`src/proxy.ts` skips `_next`, `api` and any path with a file extension — static
assets never pay locale-negotiation cost.

## 3. SEO

### Metadata

Every route exports `generateMetadata` with a localized title/description and
`alternates`:

```ts
alternates: {
  canonical: `/${locale}/programs`,
  languages: { en: "/en/programs", fr: "/fr/programs" },
}
```

Canonical + hreflang matter here: without them the EN and FR pages compete as
duplicates and both rank worse.

`metadataBase` comes from `NEXT_PUBLIC_SITE_URL` — set it per environment or
Open Graph URLs point at localhost.

Localized routes resolve unprefixed links through `src/proxy.ts`. The locale
layout supplies the Trustech shield as the default Open Graph and Twitter card
image; page-specific titles and descriptions are used for link previews.

### Structured data

Program detail pages emit `EducationalOccupationalProgram` JSON-LD (provider,
duration, offers) for rich snippets.

Serialize with `jsonLdScript()` from `lib/json-ld.ts` — **never** raw
`JSON.stringify` into a `<script>`. CMS text containing `</script>` would close
the tag early and inject markup (XSS). The helper escapes `<`, `>`, `&` and
U+2028/9.

Validate: https://search.google.com/test/rich-results

### sitemap.xml / robots.txt

Generated by `app/sitemap.ts` and `app/robots.ts` — both iterate
`routing.locales`, so a new locale is picked up automatically.

`robots.ts` **disallows everything unless `NEXT_PUBLIC_ENV=production`.** That's
deliberate: an indexed staging site splits ranking with production and is
miserable to undo. Set it correctly on the production deploy — and only there.

`sitemap.ts` lists public static pages and the currently published program,
news, event, and gallery slugs from the public API. It paginates the list
endpoints, emits both locale URLs with hreflang alternates, and omits login,
application, and status routes. If one CMS section is temporarily unreachable,
the other sections and static routes remain available; the sitemap is rendered
on request so an API outage during a build cannot freeze an empty list.

### Checklist for a new public page

- [ ] `generateMetadata` with localized title + description (≤ 160 chars)
- [ ] `canonical` + `languages` alternates
- [ ] Exactly one `<h1>`, headings in order (no skipping levels)
- [ ] `revalidate` literal set appropriately
- [ ] Images via `next/image`, sized, meaningful `alt`
- [ ] Structured data if it maps to a schema.org type
- [ ] Added to `sitemap.ts` if it's a new route pattern
- [ ] Localized slug plan (see I18N.md §7)

## 4. Before merging a UI change

- [ ] `npm run build` — check the route table; nothing unexpectedly became `ƒ` (dynamic)
- [ ] Lighthouse mobile still > 90 / SEO > 95 / a11y > 95
- [ ] No new `"use client"` on a layout or page (leaves only)
- [ ] Renders at **320px**
- [ ] Keyboard-navigable, focus visible
- [ ] Both EN and FR checked for overflow (French runs ~15–20% longer)
